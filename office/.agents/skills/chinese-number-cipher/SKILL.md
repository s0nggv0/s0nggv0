# 数字换大写中文（轻量文本加密）

## 这是什么

一个替换式编码：把文本里的 0-9 逐位换成中文大写数字，其他内容一律不动。可逆、不丢信息。
注意：这是**替换式编码**，不是密码学加密。用户若要求“真正安全 / 防破解 / 需要密钥”，先明确告知这一点，不要假装它安全。

## 触发与判定

- 用户说“加密”并给出文本 → 执行【加密】；没给文本就只问文本，不要自己编。
- 用户说“解密 / 还原 / 解回来 / 变回数字” → 执行【解密】。
- 用户只发来一段文本、没说要做什么 → 不主动改，先问一句要不要加密。
- 一次对话里用户说过“以后我说加密就照这个来”，之后收到“加密”就默认沿用本规则。

## 对照表（加密，大写数字）

| 原字符 | 替换为 |
|---|---|
| 0 | 零 |
| 1 | 壹 |
| 2 | 贰 |
| 3 | 叁 |
| 4 | 肆 |
| 5 | 伍 |
| 6 | 陆 |
| 7 | 柒 |
| 8 | 捌 |
| 9 | 玖 |
| . | 点 |
| - （数字前的负号） | 负 |
| , （千分位逗号） | 直接删除 |

解密时反向查表：零/〇 → 0，壹→1，贰→2，叁→3，肆→4，伍→5，陆→6，柒→7，捌→8，玖→9，点 → .，负 → -。
解密时也兼容小写中文数字（一二三四五六七八九），一并还原成阿拉伯数字。

## 处理细则

1. **逐位替换，不合并读数**。`2024` → `贰零贰肆`，不是 `贰仟零贰拾肆`。这样才能原样还原。
2. **只动数字**。字母、汉字、标点、空格、换行、单位、百分号、货币符号、emoji 全部原样保留。
3. **已经是中文数字的不动**。`三室两厅 3 号楼` → `三室两厅 叁 号楼`。
4. **小数、负号、范围、型号、日期、电话、IP、长编号都照此处理**：`3.14` → `叁点壹肆`；`138-1234-5678` → `壹叁捌-壹贰叁肆-伍陆柒捌`（连字符是分隔符，不是负号，保留原样）。
5. **区分负号与分隔符**：`-15%` 里的 `-` 是负号 → `负壹伍%`；`2024-05-17` 里的是日期分隔符 → 保留 `-`。
6. **原文里的千分位逗号删除**：`1,280` → `壹贰捌零`；普通句读逗号不动。
7. **完整输出，不省略不打码**。长文本从头到尾处理完，不用「……（中间略）」。
8. **默认只给结果**。一行结果直接给，最多再加一句必要说明。不要解释映射规则、不要列处理过程、不要总结意义——用户要的是密文本身。
9. **不改写原文其他措辞**。哪怕原文有错别字、语病、脏话，也只替换数字，一个字都不润色。

## 可选项（用户主动提出才用）

- 「按数值读法 / 读出来」：整串数字按中文数词读，`1280` → `壹仟贰佰捌拾`。仅用于人类阅读，不再保证可逆。
- 「小写就行」：用户明确说要用小写中文数字时，改回 〇一二三四五六七八九 那套。
- 「全角 / 带符号」：用户要更花哨时，可把结果整体套上 `【】` 之类括号，或数字后加间隔空格。默认不加。

## 示例

输入：`订单号 20240517，金额 1280.5 元，折扣 -15%，电话 138-1234-5678`
加密：`订单号 贰零贰肆零伍壹柒，金额 壹贰捌零点伍 元，折扣 负壹伍%，电话 壹叁捌-壹贰叁肆-伍陆柒捌`

输入：`我住 3 号楼 2 单元，门牌 A-1203。`
加密：`我住 叁 号楼 贰 单元，门牌 A-壹贰零叁。`

输入：`IP 是 192.168.1.100，端口 8080。`
加密：`IP 是 壹玖贰点壹陆捌点壹点壹零零，端口 捌零捌零。`

解密：`贰零贰肆年第 叁 季度` → `2024年第 3 季度`

## 常见坑

- 把 `2024` 读成 `贰仟零贰拾肆` → 错，破坏了逐位可逆规则。
- 把日期连字符当负号 → 错，日期会变形。
- 混用大小写数字（壹/一 乱用）→ 错，整套要保持统一的大写。
- 顺手「优化」原文语句或补标点 → 错，越界了。
- 只处理开头几个数字就收尾 → 错，必须整篇处理。
